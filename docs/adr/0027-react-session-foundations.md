## Fetch / money / CSRF

ApiClient accepts same-origin `/api/` paths only, including normalized-path checks, sends Identity cookies with `credentials: same-origin`, uses no-store, honors AbortSignal, and refuses redirect/HTML/malformed success JSON. Check response.ok **before** using data; an error HTTP status wins over an inconsistent body.status. Parse the documented ProblemDetails code/traceId/errors and fallback to X-Trace-Id for non-JSON failures. Preserve Retry-After, normalize field-name lookup case-insensitively without discarding original errors, and render escaped text. Network failures remain failures; they are not empty data/guest success. A real 204 is valid without parsing a body.

Unsafe requests retrieve GET `/api/auth/antiforgery`, keep requestToken/headerName **only in memory**, then submit X-CSRF-TOKEN. Dedupe token retrieval within the current generation; invalidation rejects a late old-identity token before it can authorize a POST. Login/logout invalidate old state and retrieve fresh antiforgery state after cookie changes and `/me` verification. Registration is not login: a successful 201 shows account creation, leaves current session unchanged, and invalidates the token for the next unsafe request. CSRF errors are surfaced with code/trace; the next deliberate attempt gets a fresh token. Never blindly replay a POST. Query/mutation automatic retries are disabled.

Money DTO fields remain **strings**. Exact helpers parse unsigned v1 money into bigint cents, validate scale/range, and format/serialize explicitly; no money passes through JavaScript Number. Orders display backend totals. Current helpers target nonnegative order/catalog values; signed report-net UI remains a later reporting screen, not an invented frontend feature.

## Session and cache lifetime

Construct one QueryClient and SessionController outside React rendering. Query defaults: staleTime=30s, gcTime=5min, retry=false, refetchOnWindowFocus=false; explicit session revalidation handles focus privacy. All query definitions use key factories/queryOptions. Public health has no user scope; orders use `['private', userId, 'orders', {page,pageSize,status}]`. All data-changing filters participate in keys. The private singleton `['private','session']` bootstraps identity before a user ID is known, has staleTime/gcTime zero, and is consumed only by SessionController. No query cache is persisted.

Session phases are restoring/changing/anonymous/authenticated/unavailable. Fetch `/me` through TanStack Query; **only 401** means anonymous. DB/network/config errors mean unavailable and gate protected content. A login DTO or a register response never becomes authentication authority: `/me` verifies the actual cookie. Local session metadata is ephemeral React context/external-store state derived from that server response, not a Zustand auth/role store.

Before sending a login/account-switch/logout request: increment the identity generation, hide protected content, cancel private queries, remove private cached values and clear mutation metadata. Credentials themselves are not placed in TanStack mutation variables; auth forms call the coordinator directly and do not persist their password. Public query data can remain. A failed/uncertain login/logout stays an error and re-verifies the actual surviving cookie; do not manufacture logged-out success.

Private requests capture userId/generation and check both on success **and error**. Ignore late old-identity data and late 401s, even when a transport ignores cancellation. Current-scope 401 clears private state and routes to sign-in with the original error reference. The orders DTO also verifies returned CustomerId against its expected scope, detecting an externally changed cookie before putting another owner's rows under the wrong key. Backend authorization/owner SQL still supplies the security boundary; client roles only choose navigation UX. A Customer-modified persisted `roles: Admin` cannot authorize an API call.

On hidden/pagehide, purge private state. On focus, visibility return or persisted pageshow, hide/re-verify before resuming protected views. BroadcastChannel sends only opaque source + changing/settled signals across same-origin tabs, with no credentials/token/user payload; recipients purge and re-read `/me`. Tests cover two live tabs sharing cookies and account changes. This is browser coordination, not continuous cross-device revocation or instant erasure of pixels in a suspended/unresponsive tab. Cookie changes outside this app are learned on focus/restore, a current-scope 401 or an owner-mismatch read. The backend checks every request and retains its existing 8-hour ticket/5-minute stamp policy. No frontend permission or timer authorizes business actions.

Zustand contains only density + mobile drawer UI state. Persist versioned **density only**, whitelist merge values, and discard unknown persisted fields; mobileOpen, user/email/roles, prices, orders, passwords and CSRF/tickets are not persisted. No cart or uncertain-checkout recovery store is added before its actual milestone.

## UX and routing

Use a restrained teal/navy workspace, inline decorative SVG, responsive sidebar/drawer, skip link, named navigation, heading focus, modal drawer focus trap/Escape/return focus, labeled forms, password autocomplete/hints, native constraints plus server field errors, reduced-motion behavior, and loading/empty/error/retry/404/role-denied views. Empty orders appear only for a successful empty API page. Keep unknown/unavailable sessions distinct from signed-out facts. Routes: `/`, `/login`, `/register`, `/account`, `/orders`. Protected route return paths are allowlisted; no external/open redirect. Registration explicitly asks the user to sign in after actual 201. Order dates display in device time zone; server UTC timestamps remain unchanged. Read DTO expiry metadata is advisory, never a local payment/stock decision.

Development browser origin is Vite on loopback; proxy `/api` to the API, preserving original Host and cookie scope, no CORS or bearer plumbing. Explicit Development-only backend insecure-HTTP opt-in uses the existing Dev cookies; production HTTPS defaults are unchanged. Production same-origin static/history fallback/proxy deployment remains 25/26. A local static build is not a deployment claim.
