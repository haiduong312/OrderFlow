# ADR-032: Local deployment profile with replicated hosts

Status: accepted, 2026-11-17. Scope: requested deployment milestone26; no public deployment.

## Decision

Keep `compose.yaml --profile dev` PostgreSQL-only. Broker/email/cache/realtime remain opt-in. Add standalone `compose.deploy.yaml --profile deploy` with built React/nginx TLS edge, two API and two Worker processes, PostgreSQL, RabbitMQ and Redis. Optional demo and telemetry overlays enable the existing development adapters and dashboard. One internal backend bridge carries private dependencies; a separate edge bridge permits only explicit loopback port publications. Do not reuse developer volume names, embed credentials, or remove volumes.

Multi-stage builds use locked restores/npm ci and immutable image digests. MCR does not publish the Ubuntu-packaged host SDK tag10.0.115. Keep the host pin unchanged and explicitly select published MCR SDK10.0.404-noble in a container-only global.json; final .NET images use10.0.15-noble. React builds with Node24.19.0/npm11.17.0, served by nginx stable1.30.6-alpine. Final custom images have non-root identities, read-only roots, dropped capabilities and tmpfs scratch space. Standard profile also uses no-new-privileges. The local snap Docker/AppArmor combination fails even `/bin/sh` execution with that flag; a separately named, explicit compatibility override disables only this flag, never the default.

## Identity, edge and realtime

Only the fixed backend address of the nginx proxy is trusted for one symmetric hop of forwarded For/Proto/Host. It overwrites incoming forwarded headers and accepts only the configured public DNS host. Middleware runs before auth, origin checks and IP rate limiting. Browser frontend/API/hub share HTTPS origin; no direct API host ports or CORS exception. Proxy retries of uncertain requests are disabled. Docker DNS resolution refreshes replaced API addresses; this is not zero-downtime failover.

The supported hub remains WebSockets **with negotiation**. nginx1.30.6 includes OSS sticky cookies (introduced1.29.6). A Secure/HttpOnly/SameSite=Lax path-scoped routing cookie pins negotiation and upgrade to a named API route. Ordinary API calls round robin, including login/me/antiforgery. Redis fans hints out across nodes; it does not share connection tokens or make long-poll/SSE supported. Node failure loses the socket/token: renegotiate and refetch durable HTTP state. Redis hints can be lost/duplicated.

API replicas share a0700 key-ring volume, UID1654, application discriminator OrderFlow.Deployment and wrapping certificate. PersistKeysToFileSystem plus ProtectKeysWithCertificate explicitly encrypts key XML; PostgreSQL sharing alone is insufficient. Wrapping private key/password are separate mounted secrets, never in the volume/image/frontend. Local Compose secrets are ordinary host bind files, not an encrypted secret manager. Production requires restricted host/volume backups and wrapping keys protected at rest by an appropriate secret/KMS/HSM mechanism. Certificate rotation/decrypting old rings requires a planned additional decryption-key configuration; do not replace the current certificate and invalidate existing data blindly.

## Startup and coordination

Run the explicit `migrate` CLI once with a schema-owner credential, before starting new-schema hosts. It applies existing migrations, role definitions and fixed grants for separate non-owner API/Worker logins. Runtime roles cannot write migration history or perform schema DDL. Normal startup never migrates/seeds. New-volume initialization creates database roles; existing-volume upgrades need reviewed role provisioning instead of rerunning initialization or resetting data.

API readiness/admission depends on PostgreSQL/schema; it has no Compose broker/Redis health prerequisite. Worker dependency readiness additionally checks enabled RabbitMQ/SMTP. Startup probes retry eight times with2s gaps and existing probe time budgets, then fail visibly. Compose services wait for required health and use on-failure:3; Docker health alone does not restart a container. A faulted BackgroundService now yields process exit1 after the host has shut down, so the restart policy can recognize failure. Normal SIGTERM remains graceful. In the deployment profile optional API realtime dispatch has StopHostOnDispatchFailure=false: finite broker retries then event2407/metric and dispatcher suspension; HTTP checkout/readiness continues. Repair and restart to resume dispatch. Other hosts retain their previous fail-host default. This explicitly refines ADR-031's dependency policy; it does not hide database failures or retry business mutations.

Correctness remains in existing PostgreSQL row locks, idempotency uniqueness, reservation guards, SKIP LOCKED claims, fenced leases and inbox deduplication. No cross-process application lock is introduced. Graceful host shutdown budget25s is below Compose30s (nginx20s/SIGQUIT). A forced crash may redeliver; no exactly-once external effect is claimed. Rate-limit windows remain per process/IP,20 auth writes/60 reads per minute, not a strict cluster quota.

The simulator, SMTP and internal HTTP OTLP need container DNS names. Extend their existing validators with explicit opt-ins for exactly simulator:8090, mailpit and telemetry:4318. Simulator/payment/SMTP retain Development/Testing environment restrictions; API cookies remain Production/secure. This narrowly supersedes the loopback-only adapter transport descriptions in ADR-018/023/031 for the optional local Docker profile. No production payment/email provider is implemented.

The optional telemetry overlay sets four fixed service.instance.id values (api1/api2/worker1/worker2) through validated Telemetry:InstanceName. This prevents cumulative counters from separate processes colliding; labels never include business identities. Default host telemetry still omits an instance unless configured. Shared-DB gauges use MAX across replicas, per-process counter rates can sum. Actual local ingestion verifies four resource identities and one order trace containing API and Worker checkout/publication/handling spans.

## Evidence and limits

See [deployment runbook](../deployment.md) and [implementation status](../implementation-status.md) for exact results. Opt-in tests exercise separate real processes through TLS with a pinned fixture certificate. SQL row/advisory barriers verify both API/Worker participants reached contested operations. Other tests cover encrypted key sharing, trusted/untrusted forwarding and optional dispatch failure. Existing domain/SQL/security/recovery suites remain applicable. Single edge/DB/broker/Redis and host-local volumes are deliberate local simplifications, not HA, production backup, rolling-upgrade compatibility or global quota guarantees.
