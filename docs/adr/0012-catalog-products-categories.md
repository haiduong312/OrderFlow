# ADR-012: Catalog categories, archival, concurrency and literal substring search

Date: 2026-11-03. Status: Accepted. Supplements ADR-001/006/008/011 and the original product-only Catalog contract.

## Decision

Milestone 07 adds Categories and Products in the catalog schema, not Inventory. Each product has one required Category FK (restrict deletion). IDs are server-generated UUIDs and never changed by updates. Category names are labels, not unique keys: trimmed, required, <=200 characters; duplicate labels are allowed and IDs disambiguate them. Category trees/slugs are deferred.

Products retain immutable normalized ASCII SKU (trim/uppercase, 1–64 letters/digits/hyphens), trimmed required name <=200, optional description represented as empty text <=2000, positive USD numeric(18,2), active flag and positive integer version. Unique SKU is global, including archived products; SKU reuse never repurposes a historical identifier. HTTP updates accept neither SKU nor any inventory field. Application-managed version is an EF concurrency token; successful updates increment it. Stale versions return 409 version_conflict. Archive requires expectedVersion; repeated archive with current version returns unchanged representation/version. Even no-op archive uses a conditional version UPDATE to avoid acknowledging a concurrent reactivation. Version exhaustion returns state_conflict.

Public (anonymous/Customer) reads expose only Product.IsActive AND Category.IsActive; archived/absent detail returns the same 404. Public categories include active categories, even empty ones. Admin reads include all rows and category activity. Archiving a category changes only that category: products keep their own active/version flags but disappear from public list/detail. Restoring the category restores visibility only for products still individually active. Product/category restoration uses PUT isActive=true. Product create/content update requires an active target category; archiving a product remains possible under an archived category. No physical DELETE endpoint is provided. Later Order line FKs/snapshots must preserve historical products; no nonexistent Order reference test is claimed now.

Category assignment and category archival coordinate in PostgreSQL. Product create/update locks the target Category FOR UPDATE in a short transaction, checks fresh state using a no-tracking locking query (never a stale tracked entity), then writes the product. Category changes serialize through their UPDATE and version guard. This adds a catalog lock level: Category rows before Product writes; product-only archive skips Category locking. No external calls occur in these transactions. Later checkout must extend the documented global lock order, validate category/product association under its locks and enforce effective activity; this milestone implements no checkout. Only named SKU unique violation and EF concurrency conflicts get expected 409 mappings; unclassified infrastructure failures remain failures.

Public/admin lists are bounded (default page 1/20, pageSize 1–100, signed-int offset bound). All filters precede count/paging; read queries use AsNoTracking and server-side DTO projection. Products support q (<=100 raw characters, trim; empty means no search), categoryId and sort newest/name/price-asc/price-desc. Categories support q and newest/name. Every sort ends with unique Id: newest CreatedAt DESC/Id DESC; name ASC/Id ASC; price ASC/Id ASC or price DESC/Id DESC. Unknown category filter yields empty list; empty/malformed UUID is 400. Past-end page is empty with filtered totalCount. Count and page are sequential Read Committed statements, not a frozen snapshot across concurrent edits.

Search is parameterized PostgreSQL ILIKE '%literal%' on product name OR SKU, and category name. Escape backslash, percent and underscore so the keyword is a literal substring, not a wildcard language. Case folding follows the database collation; no accent removal or full-text/token semantics. B-tree indexes support SKU uniqueness/exact lookup and createdAt/Id or category/createdAt/Id ordering/filtering. They do NOT accelerate arbitrary leading-wildcard substring searches; baseline small-catalog search may scan/sort rows. No pg_trgm extension/GIN index or search-performance guarantee is added; measure actual plans/data before selecting one.

DTOs explicitly expose money as invariant strings and fixed currency USD. No timestamp is exposed until needed; CreatedAt is stored UTC at microsecond precision for ordering. Catalog-specific OpenAPI property schemas describe positive money and required non-null update fields without changing shared money semantics. No cache, file upload, image fetching, fake stock count, pricing total or order snapshot implementation is introduced. Existing spec's stock summaries/available count remain milestones 08/09; API responses deliberately contain no inventory fields yet.

## Consequences and verification

Archive visibility can change when category state changes without changing product version; future client invalidation must account for that. Category row locks serialize assignment through one category, a correctness/throughput trade-off. Future checkout must revalidate eligibility rather than trust a prior catalog read. Offset pages can move under concurrent edits; count/page are not an atomic snapshot. DB numeric storage has scale 2 and can coerce raw SQL input; HTTP/domain reject extra scale instead of relying on coercion.

Domain tests, actual PostgreSQL constraints/migration/HTTP tests, literal wildcard search, filtered page boundaries and unique tie-breakers, archival/restore, permissions/CSRF, no inventory updates and OpenAPI schema tests are required. Race gates synchronize independent request DbContexts before SKU inserts or category locks after version reads; no sleeps establish correctness.
