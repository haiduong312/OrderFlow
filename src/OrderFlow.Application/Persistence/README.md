# Persistence boundary

Contains the single scoped Identity-compatible OrderFlowDbContext, explicit Identity/reliability/Catalog/Inventory/Ordering mappings, converters, design-time factory and migrations. Configuration is private via ConnectionStrings__OrderFlow; hosts never migrate automatically. See docs/persistence.md for dedicated migrate/seed commands and actual PostgreSQL tests.

Checkout and other application use cases share one context for an atomic operation, including idempotency response/outbox/inbox writes. Never share that instance across parallel tasks or commit a claim in an independent store, and do not wrap every EF operation in a generic repository. Runtime hosts compose the application; schema changes are explicit operator actions. Catalog alone owns Categories/Products. Inventory owns balance writes and immutable movements; Product initialization is protected by a reviewed database trigger. Order/OrderItems/OrderStatusHistory and Active/Released InventoryReservations now persist through checkout in that same transaction. Cancellation/expiry release and Admin forward fulfillment share this context/transaction; the separate Worker now drives OrderExpiryProcessor with one scoped transaction per order; payment consumption remains future work.
